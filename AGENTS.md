# AI Agent Instructions — BIMSpend

Read these instructions before doing any work in this repository. This project is an exploratory brainstorming and product-discovery knowledge base, NOT an approved software project.

## 1. Read the foundation documents first

Read `README.md` and `CONTEXT_FOR_AI.md` in full before proposing anything. Then read `docs/decisions/decision-log.md` and the latest brainstorming notes under `docs/`.

## 2. Distinguish ideas from approved decisions

- An **IDEA** or **HYPOTHESIS** is a proposal under investigation. It may be rejected or deferred at any time.
- A decision is **APPROVED** only when the user has explicitly approved it. Never label an idea APPROVED on your own.
- Record status in `docs/decisions/decision-log.md` using the format: `YYYY-MM-DD | Idea / Hypothesis / Tested / Approved | Topic | Evidence | Decision / Next action`.

## 3. Never invent research findings

Do not fabricate competitor capabilities, links, pricing, journal-file contents, or financial data. If a fact is not in the repository, mark it as unverified and say so. Use only synthetic or explicitly labelled data in examples.

## 4. Never assume software development has been authorized

Do not write implementation code, build plugins, create production Autodesk add-ins, install tracking services, or collect activity data. This repository is for documentation, research organization, and brainstorming only.

## 5. Preserve existing documentation

Do not delete, overwrite, or discard original brainstorming material merely because it is preliminary or uncertain. Move or reorganize files only with a clear reason; keep one canonical copy of each document.

## 6. Update project context after meaningful discussions

Append new questions, findings, and decisions to the relevant docs and to `CONTEXT_FOR_AI.md`. Keep a running decision log.

## 7. Record important changes in the changelog

Append entries to `CHANGELOG.md` for meaningful structural or content changes.

## 8. Keep sensitive information out of GitHub

Never commit client/project names, employee-identifiable records, rate cards, invoices, journal files, original spreadsheets, secrets, or credentials. Raw company data stays outside git unless the user explicitly authorizes inclusion. See `.gitignore`.

## 9. Use GitHub Issues for discrete investigations

Open an Issue for each distinct research question. Do not turn brainstorm notes into requirements without explicit user approval.

## 10. Mobile/continuation-friendly

Assume the next reader is a different AI agent on a different device. Write clearly, use descriptive filenames, link between documents, and keep `CONTEXT_FOR_AI.md` current so a new conversation can resume without the user repeating prior discussions.
